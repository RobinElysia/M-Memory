# 冲突消解

## 为什么需要冲突消解？

用户在与 Agent 的长对话中可能说前后矛盾的话：

- "我住在北京" → 3 天后 → "我搬到上海了"
- "Python 2 是最好的" → 后来 → "应该用 Python 3"

普通 RAG 会把两条信息都检索出来，按向量相似度排序，但没有"纠错"能力。
冲突消解管线专门解决这个问题。

## 完整管线

```
候选节点集 (unordered)
  │
  ├──→ [加权重排序]
  │    score = 0.5·sim(C, query) + 0.3/(1+ΔT) + 0.2·confidence
  │    → 截断至 top_n
  │
  ├──→ [LLM 矛盾检测]
  │    输入：候选节点的内容、时间戳、置信度
  │    输出：[{"newer_id": 0, "older_id": 1, "reason": "..."}]
  │
  └──→ [过时降权]
       旧节点 is_stale = True
       旧节点 confidence *= 0.1
       保留（不删除）
```

## 重排序公式详解

```
score = α · sim(C, query) + β / (1 + ΔT_days) + γ · confidence
```

- **α = 0.5**：内容相似度。内容与查询越相关，分数越高。
- **β = 0.3**：时间衰减。`ΔT_days` 是以天为单位的时间差。  
  当 ΔT = 0（刚刚写入）→ 时间因子 = 1.0  
  当 ΔT = 9 天 → 时间因子 = 0.1  
  当 ΔT → ∞ → 时间因子 → 0
- **γ = 0.2**：来源置信度。来自高置信度源的信息优先。

## 为什么不删除旧信息？

旧信息被降权而非删除，原因是：

1. **深层回溯**：用户可能问"你之前说我在哪里来着？"
2. **上下文参考**：新信息可能需要旧信息作为对比
3. **错误恢复**：如果 LLM 误判矛盾，旧信息仍在，可恢复
